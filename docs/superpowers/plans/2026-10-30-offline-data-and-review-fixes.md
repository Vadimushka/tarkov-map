# Данные внутри exe и правки по ревью

**Goal:** exe можно отдать другу: все данные карт уже внутри и работают без сети;
плюс правки, накопившиеся в ревью.

**Architecture:** снимок кэша (`maps.json`, `{pve,regular}_maps*.json`,
`{pve,regular}_items_ru.json`, `svg/*.svg`) лежит в `assets/data.zip`, который
`main.go` встраивает через `go:embed` и передаёт в `data.Store` как `Seed`.
Store подкладывает файл из снимка в кэш, если файла нет или снимок новее; время
файла — время снимка, поэтому дальше работает прежняя логика: устарел — фоновое
обновление из сети, сети нет — живём на снимке. Снимок делает `scripts/seed`
(тот же Store качает всё в пустую папку и пакует в zip).

**Tech Stack:** Go 1.2x stdlib (`archive/zip`, `embed`, `io/fs`), Wails v2, JS.

**Spec:** запрос владельца 30.10.2026: «все данные должны лежать в zip архиве или в
самом exe, чтобы я мог этот exe передать другу» и «сделай правки по ревью».
Отдельного дизайна нет — решения ниже мои.

## Global Constraints

- Сеть — только GET к json.tarkov.dev, assets.tarkov.dev, raw.githubusercontent.com.
- Не трогать процесс и память игры, без оверлеев; скриншоты не удалять и не открывать.
- Чужие инструменты через `go run …@версия` не запускать — только стандартная библиотека.
- Коммиты на русском, почта vadimushka.d@gmail.com.

## Решения

- Снимок — один zip внутри exe (не рядом): другу передаётся один файл.
- Сеть не отключается: снимок — стартовые данные, после патчей игры приложение само
  обновит их с tarkov.dev, если тот доступен.
- `assets/data.zip` коммитится: сборка воспроизводима без сети; обновляется
  `scripts/seed` перед сборкой для передачи.

## Задачи

1. **Seed в Store.** `Store.Seed fs.FS`; `seed(name)` подкладывает файл, если его нет или
   снимок новее, время = время записи в zip. Зовётся в `LoadCached` (файлы режима и
   названия) и в `SVG`. Тесты: пустой кэш + снимок → `LoadCached` работает без сети;
   кэш старше снимка заменяется; свежий кэш не трогается; SVG из снимка.
2. **Фоновое обновление качает только устаревшие файлы** (правка ревью «9 МБ при каждом
   запуске»): `Fetch(mode, force)`; кнопка — `force`. Тест: свежие карты + старые
   названия → качаются только названия.
3. **`scripts/seed`** → `assets/data.zip`; `Store.SVGDefs()`; `main.go` встраивает zip;
   `build.sh` без изменений (zip уже в репозитории).
4. **Правки Go:** порядок сохранения настроек (`smu`), Glob со скобками в пути
   (`os.ReadDir` + `filepath.Match`), ожидание появления папки скриншотов, битый
   `items_ru` — в лог, ссылка на спецификацию PE/COFF в `syso.go`.
5. **Правки фронтенда:** «найдена 1 точка», один крестик в поиске, подсказка прячется
   при пересборке слоя, поле поиска оживает после карты без названий, слой лута
   строится один раз, подсказка точки без известных названий, кнопка «Обновить
   данные» заблокирована на время обновления, SVG чистится от скриптов и `on*`.
6. **Сборка и проверка** на пустом кэше без сети (подменённый адрес), ревью ветки.

## Review Focus

- Повреждённый или неполный zip внутри exe — карта всё равно должна открываться из
  сети или кэша, а не падать.
- Снимок старее кэша — кэш не откатывается.
- Друг играет в PvP — данные `regular` тоже в снимке.
- Две копии приложения одновременно (общий кэш) — подкладывание атомарно.
- Папка скриншотов появилась после запуска — скрины подхватываются без перезапуска.
