# Tarkov Map — дизайн приложения

Дата: 2026-10-28. Статус: черновик на утверждение.

## Зачем

Владелец играет в Escape from Tarkov (сейчас в основном PvE) и пользуется картой
tarkov-market.com (TM) + их PowerShell-скриптом. Что не устраивает в TM:

- нужно держать открытым сайт в браузере;
- неудобный фильтр — на карте слишком много всего, нельзя оставить только нужное;
- направление взгляда доступно только с Pro;
- скрипт TM удаляет скриншоты при смене карты и отправляет данные на чужой сервер.

Нужно своё приложение для Windows: тыкнул exe — открылось окно с картой текущей
локации, на которой видно, где ты (по скриншоту), куда смотришь, где выходы,
квестовые точки и лут — и только то, что выбрано в фильтре.

Приложение личное: один пользователь, один ПК, без продажи и публикации.

## Цели

1. **Позиция по скриншоту.** Игрок жмёт клавишу скриншота в игре (у владельца — `\`).
   Приложение замечает новый файл, разбирает координаты из имени файла и ставит
   метку на карте с конусом направления взгляда. Точки текущего рейда соединяются
   в маршрут.
2. **Автосмена карты** при загрузке в локацию — по логам игры.
3. **Слои на карте:** выходы (ЧВК / Дикие / совместные, с пометками условий: платный,
   рубильник, кооператив), переходы между картами, квестовые зоны, лут (контейнеры и
   предметы на полу), замки с ключами, опасные зоны, рубильники.
4. **Фильтр — обязательная и главная часть UI.** По умолчанию на карте ничего лишнего.
   Можно включать целые категории (например, «Выходы ЧВК», «Оружейные ящики») и
   отдельные пункты (одна квестовая цель, один тип контейнера, конкретный предмет
   на полу через поиск по названию).
5. **Активные квесты ведутся автоматически по логам игры** (взят / сдан / провален).
   Слой «Квесты» по умолчанию показывает только цели активных квестов.
6. **Этажи.** Для многоэтажных карт — переключатель этажей; при новой позиции этаж
   выбирается автоматически по высоте точки.
7. **PvE и PvP** — разные наборы данных; режим определяется по логу автоматически.
8. **Работа без сети** на закэшированных данных.
9. **Интерфейс на русском.**

## Не цели (в первой версии)

- Окно поверх игры / оверлей. Основной сценарий — окно на втором мониторе.
- Слежение за позицией в реальном времени (только по скриншотам).
- Интеграция с tarkov-market или TarkovTracker, синхронизация квестов куда-либо.
- Трей, автозапуск с Windows, автообновление приложения.
- История прошлых рейдов (маршрут живёт только в текущем рейде).
- Карты без SVG в tarkov.dev: Лаборатория, Лабиринт, Ледокол (см. «Карты»).
- Мобильная версия / доступ с телефона.

## Анти-цели (провал, даже если «работает»)

- **Что-либо, что может привести к бану BattlEye:** чтение памяти игры, внедрение в
  процесс игры (как оверлеи Discord/Steam), прозрачные «click-through» окна поверх
  игры. Приложение только читает файлы логов и имена файлов скриншотов.
- **Удаление или изменение скриншотов пользователя.** Приложение их только читает.
- **Отправка каких-либо данных наружу.** Сеть — только для скачивания карт и данных.
- **Перегруженная карта по умолчанию** — ровно то, от чего уходим с TM.

## Как устроено (проверено на реальных данных)

### Скриншоты → позиция

Имя файла скриншота EFT:

```
2026-10-28[21-06]_-312.74, 23.88, -111.95_-0.04637, 0.85289, 0.07698, 0.51430_9.75 (0).png
└ дата[чч-мм]     └ x, y, z (y — высота)  └ кватернион камеры qx, qy, qz, qw    └ (см. ниже)
```

- Регулярка, проверенная на 15 реальных скринах:
  `^(\d{4}-\d{2}-\d{2})\[(\d{2})-(\d{2})\]_(-?[\d.]+), (-?[\d.]+), (-?[\d.]+)_(-?[\d.]+), (-?[\d.]+), (-?[\d.]+), (-?[\d.]+)_`
  Числа — с точкой, парсить в инвариантной культуре.
- Направление взгляда (оси Unity): `fx = 2(qx·qz + qw·qy)`, `fz = 1 − 2(qx² + qy²)`.
- Последнее число (9.75 … 13.67 за 34 реальные минуты) — вероятно, игровое время
  суток в часах; приложению не нужно, можно показывать в подсказке.
- Дубликаты: игра пишет `(0)`, `(1)` для скринов в одну секунду с одинаковыми
  координатами — склеивать.
- Отслеживать создание `*.png` (fsnotify). В маршрут текущего рейда попадают только
  скрины, созданные после начала рейда.

### Игровые координаты → точка на карте (как в tarkov.dev)

Параметры карты берутся из `maps.json` tarkov.dev: `transform [sx, mx, sy, my]`,
`coordinateRotation` (градусы), `bounds` (два угла **в порядке [x, z]**), опционально
`svgBounds`, `svgPath`, `svgLayer` (базовый слой), `layers[]` (этажи: `svgLayer`,
`extents[{height:[lo,hi], bounds:[[[x,z],[x,z],"имя"]]}]`).

```
project(x, z):
  r = rotation·π/180;  rx = x·cos r − z·sin r;  ry = x·sin r + z·cos r
  return (sx·rx + mx,  −sy·ry + my)
```

SVG растягивается на прямоугольник между `project(minX, maxZ)` и `project(maxX, minZ)`
из `svgBounds || bounds` (min/max по каждой оси), с `preserveAspectRatio` по умолчанию
(как Leaflet). Маркер на этаже, если его `y` в `[lo, hi)` и `(x, z)` внутри одного из
прямоугольников `extents.bounds`; иначе — базовый слой. Этажи в SVG — верхнеуровневые
`<g id="...">`.

**Проверено:** спайк в `C:\Users\vadimushka_d\Tools\TarkovMap\spike\` (route.html,
build.ps1) нарисовал реальный маршрут по Развязке — владелец подтвердил, что точки
совпадают с тем, где он ходил. Код спайка можно брать за основу фронтенда.

### Логи → карта, режим, рейд, квесты

Папка: `<игра>\build\Logs\log_<дата>_<версия>\`, на каждый запуск игры — новая
подпапка; брать самую свежую по времени создания и переключаться, когда появляется
новая. Файлы читать в режиме совместного доступа, неполную последнюю строку не
потреблять.

**Логи живут недолго** (у владельца в `Logs` всего 4 папки: одна за август, три за
28.10), поэтому приложение хранит своё состояние само (в `%LOCALAPPDATA%\TarkovMap\`):
список квестов по режимам, границу учёта квестов, позиции чтения по файлам и id уже
учтённых событий.

Чтение при запуске (решение исполнителя, см. ниже):

- **Текущая сессия игры** (самая свежая папка) читается **с начала**, чтобы
  восстановить режим, карту и факт «идёт рейд», если приложение запущено посреди
  рейда. Маршрут при этом восстанавливается из скринов, созданных после последнего
  `GameStarted`.
- **Квестовые события** собираются из **всех** доступных папок логов, но учитываются
  только события новее «границы учёта квестов». Повторно учтённые события
  отбрасываются по ключу `(questId, type, dt)`, поэтому перечитывание безопасно.
- Дальше — хвост файлов в реальном времени.
- **Режим переключается внутри одной сессии игры** (в 21:02 за минуту
  Pve → Regular → Pve), поэтому каждое событие относится к режиму по последней
  строке `Session mode:` перед ним. Списки квестов PvE и PvP — раздельные.

| Что | Файл | Строка |
|---|---|---|
| Режим | `*application_*.log` | `Session mode: Pve` / `Session mode: Regular` |
| Карта | `*application_*.log` | `scene preset path:maps/<bundle>.bundle` → совпадает с `scenePath` в данных tarkov.dev (`maps/shopping_mall.bundle` → interchange) |
| Карта (онлайн, доп.) | `*application_*.log` | `TRACE-NetworkGameCreate profileStatus: ... Location: <nameId>, ...` (в PvE 1.2.5 этой строки не было) |
| Старт рейда | `*application_*.log` | `GameStarted` |
| Квесты | `*push-notifications_*.log` | строка `Got notification \| ChatMessageReceived`, следом многострочный JSON до следующей строки с датой; `message.type` + `message.templateId` = `"<questId> <суффикс>"` |

Коды `message.type`: `10` — квест взят (подтверждено: 8 стартовых квестов в 21:44
после сброса профиля). `11` — провал, `12` — сдан — **не подтверждено**, это
ожидание по аналогии; проверить на первом же сданном квесте. Неизвестные коды
логировать (в отладочный журнал приложения) и не менять по ним список.

**Начальный список и сброс квестов** (решение исполнителя):

- Граница учёта квестов по умолчанию — **2026-10-28 21:41** (момент сброса
  PvE-профиля владельца). Тогда при первом запуске 8 стартовых квестов из лога 21:44
  подхватятся сами, ручная разметка не понадобится.
- Кнопка «Начать квесты заново» очищает список выбранного режима и спрашивает новую
  границу: по умолчанию — время последней загрузки профиля в логе
  (`PrepareSelectedProfileLocally` перед текущим моментом), можно указать вручную.
  После этого логи перечитываются от новой границы. Так стартовые квесты, взятые
  через пару минут после сброса, не теряются.
- Ручная правка: добавить квест в активные / убрать из активных (поиск по названию).

Сопоставление логов карт: `night-factory` → SVG Factory, `ground-zero-21` и
`ground-zero-tutorial` → SVG Ground Zero.

Что **нельзя** получить из логов: какие выходы открыты в рейде (ни одной строки),
за кого играешь (ЧВК или Дикий) — пока не найдено, нужен лог рейда за Дикого.
Поэтому сторона выбирается переключателем в UI (по умолчанию ЧВК); автоопределение —
если найдётся признак в логах.

### Данные и кэш

| Что | Откуда | Лицензия |
|---|---|---|
| Параметры карт | `https://raw.githubusercontent.com/the-hideout/tarkov-dev/HEAD/src/data/maps.json` | MIT |
| SVG карт | `svgPath` из maps.json (`https://assets.tarkov.dev/maps/svg/<Map>.svg`), запасной — raw GitHub `the-hideout/tarkov-dev-svg-maps` | CC BY-NC-SA 4.0 + запрет на читы/радары |
| Точки на картах | `https://json.tarkov.dev/{regular\|pve}/maps` + `maps_ru` (переводы по ключам) | — |
| Квесты | `https://json.tarkov.dev/{regular\|pve}/tasks` + `tasks_ru` | — |
| Предметы (названия лута) | `https://json.tarkov.dev/{regular\|pve}/items` + `items_ru` | — |

- Объёмы: `pve/maps` ≈ 8.5 МБ. Строки в данных — ключи переводов, русские названия
  берутся из `*_ru` по ключу; если перевода нет — показывать ключ/английское.
- Что есть в `maps` для каждой карты: `extracts` (name, faction pmc/scav/shared,
  position, outline, top/bottom, switches, transferItem), `transits`, `lootContainers`,
  `lootLoose` (position + id предметов), `locks` (тип, ключ), `hazards`, `switches`,
  `spawns`, `bosses`, `stationaryWeapons`, `btrStops`. В `tasks`: у целей квестов
  `zones` (position, outline, top/bottom, map) и `possibleLocations`.
- GraphQL `api.tarkov.dev` в момент проверки лежал («server unavailable»), а
  `json.tarkov.dev` работал — использовать JSON. Сам tarkov.dev берёт данные оттуда же.
- Кэш в `%LOCALAPPDATA%\TarkovMap\`: при запуске обновлять, если старше 24 ч, плюс
  кнопка «Обновить данные». Нет сети — работать на кэше. Нет сети и нет кэша —
  понятное сообщение.
- SVG и данные **не коммитить** в репозиторий — скачиваются приложением. В окне
  «О программе» — атрибуция tarkov.dev и авторов карт (требование CC BY).

### Карты в первой версии

Те, у которых в maps.json есть `svgPath`: Таможня, Завод (+ ночной), Эпицентр
(все варианты), Развязка, Маяк, Резерв, Берег, Улицы Таркова, Терминал, Лес.
Для остальных — сообщение «карта пока не поддерживается».

**Этажи без SVG-слоя** (решение исполнителя): у Резерва 2–5 этажи и у Таможни 4-й
этаж в tarkov.dev заданы только растровыми тайлами (`tilePath` без `svgLayer`).
В первой версии тайлы не используются: переключатель такого этажа показывает базовую
SVG и оставляет яркими только метки этого этажа (по `extents`), остальные приглушает.
Тайлы — возможное улучшение позже (это фактически часть Leaflet и заметный офлайн-кэш).

### Окно

Одно окно, запоминает монитор, позицию и размер. Слева панель фильтра, справа карта
(масштаб колесом, перетаскивание). Кнопка «Центр на мне». Статусная строка: режим
(PvE/PvP), карта, время последнего скрина, найдены ли пути к игре и скринам.

## Решения исполнителя (не согласованы с владельцем отдельно)

- Фронтенд на чистых HTML/JS/SVG без Leaflet и без сборщика — продолжение спайка.
- Начальная граница учёта квестов — момент сброса профиля 28.10 21:41; поведение
  кнопки «Начать квесты заново» — как описано в разделе про логи.
- Текущая сессия логов читается с начала, чтобы восстановить состояние при запуске
  посреди рейда.
- Этажи без SVG — без тайлов, только приглушение меток.
- Сторона (ЧВК/Дикий) — ручной переключатель, пока в логах не найден признак.
- Кэш и состояние — в `%LOCALAPPDATA%\TarkovMap\`, обновление данных раз в сутки.

## Оставлено на усмотрение исполнителя

- Структура Go-пакетов, способ доставки событий во фронтенд (события Wails и т.п.).
- Фронтенд — без сборщика (чистые HTML/JS/CSS) или с ним; спайк сделан на чистом JS
  и SVG без Leaflet — менять, только если упрёмся в производительность (Улицы, лут —
  до ~1300 контейнеров и ~950 точек лута на карту).
- Иконки и цвета слоёв; как выглядит поиск по предметам.
- Хранить ли фильтр отдельно для каждой карты или общий (по умолчанию — общий,
  запоминается между запусками).
- Формат файлов настроек и кэша.
- Тесты: разбор имён скринов, пересчёт координат (эталон — точки спайка), разбор
  строк логов — юнит-тестами в WSL; слежение за файлами — ручная проверка exe в Windows.

## Первый шаг плана

Проверить кросс-сборку: пустое окно Wails, собранное в WSL под `windows/amd64`,
открывается двойным кликом в Windows. Если нет — переход на сборку в GitHub Actions
(windows-latest) до того, как писать остальное.
